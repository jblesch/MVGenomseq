# Changelog
## [2.0.0] - 2026-07-29
### Added
  - Added `$id` identifying the schema by its release tag, making it referenceable via `$ref`.
  - Added optional `submission.schemaVersion` so a submission declares which schema version it conforms to.
  - **BREAKING**: Added required `donors[].labData[].caseControlStatus`, so that the case/control role of each sample is stated explicitly instead of being inferred from `diseaseType`, `relation` and `sequenceSubtype`. Those fields cannot express the distinction reliably: `relation` can misclassify affected relatives, `sequenceSubtype` permits `other`/`unknown`, and hereditary cancer is ambiguous under both. `unknown` is deliberately not offered: Leistungserbringer know the status of the samples they submit, so the value would only serve as an escape hatch that is not needed.
  - Added `aunt`, `uncle`, `grandparent` and `grandchild` to `donors[].relation`, to accommodate more complex pedigrees. Existing values are unchanged and `other` is retained. 
  - Added optional `donors[].labData[].readStructure`, describing where the UMI and barcode segments sit within the sequencing reads (`readType`, 0-based `offset`, `length`, `segmentType`). The layout is a property of the library design, so it is recorded once per lab dataset rather than repeated per file. Required for deduplication and consensus calling when research-consented submissions are reanalysed.
  - Added `donors[].labData[].umiKitName`, `umiKitManufacturer` and `customUmiUsed`, required whenever `readStructure` declares a `umi` segment and absent otherwise.
### Changed
  - **BREAKING**: `sampleConservation`, `sequenceSubtype`, `fragmentationMethod`, `enrichmentKitManufacturer`, `libraryPrepKit`, `sequencerModel`, `tissueOntology.name`, `relation`, `sequencingScope`, `sequencingLayout` and `tumorCellCount[].method` each gained a companion field named after it with the suffix `Other` (`sampleConservationOther`, `relationOther`, and so on) that is required and must be non-empty when the value is `other`. `donors[].gender` is the sole deliberate exception: `other` there is a valid self-description rather than a missing value. The entries collected there are intended to be reviewed periodically, so that recurring values can be promoted into the enums and uninformative ones followed up with the submitting Leistungserbringer. `unknown` is unaffected.
  - **BREAKING**: The manufacturer values of `donors[].labData[].enrichmentKitManufacturer` are lower-cased to `illumina`, `agilent`, `twist` and `neb`. It was the only enum in the schema mixing capitalised and lowercase values, and since enum matching is case-sensitive a submitter following the schema's otherwise uniform lowercase convention would have been rejected without being told why.
  - **BREAKING**: `donors[].labData[].sampleConservation` is adapted; `cryo-frozen` is replaced by `freezer`, `ultra-low-freezer` and `cryogenic-freezer`, so that storage temperature is recorded rather than lost; `refrigerator` and `none` are new. `fresh-tissue` is retained. Submissions using `cryo-frozen` no longer validate.
  - **BREAKING**: `donors[].labData[].libraryPrepKit` and `sequencerModel` are now controlled, adopting the `library_preparation_kit_retail_name` (171 values) and `instrument_model` (67 values) vocabularies of the GHGA ExperimentMethod entity. Where `other` is used, the new `libraryPrepKitOther` and `sequencerModelOther` must name the kit or model. Free-text values no longer validate.
  - **BREAKING**: The two vocabularies above live in separate files under `GRZ/vocabularies/` and are pulled into the schema with `$ref`, to keep `grz-schema.json` itself readable. Validators must be given the vocabulary files as well as the schema. 
  - **BREAKING**: Replaced `donors[].labData[].libraryType` with two required fields, `platformCategory` and `sequencingScope`. The old enum encoded two independent facts in a single value: the stem named *what* was sequenced (genome, exome, panel) while the `_lr` suffix named *how* it was sequenced (long read). A single enum then has to list every combination of the two, and this one did not: there was no `other_lr` or `unknown_lr`, so a long-read run of an unusual or unstated scope could not record that it was long-read at all. The suffix was also invisible to validation, since nothing constrained it to a known set of platforms, and any consumer wanting only the platform had to parse the value rather than read a field. Separating the axes makes each fact independently stated, filterable and extensible: a new scope adds one value instead of two, a new platform category does not double the list, and neither axis constrains the other.
  - **BREAKING**: `wes` is gone. It was a synonym of `wxs`, so two submitters could describe an identical experiment differently with nothing to catch it. 
  - **BREAKING**: Removed `reverse` from `donors[].labData[].sequencingLayout`. The field states how many reads were produced per fragment, one or two, whereas `reverse` describes which direction a read represents — an orthogonal property. A run recorded as `reverse` is in fact single-end, so the value left a consumer unable to tell how many read files to expect. Read direction is now carried where it belongs: which read a file holds is given by `sequenceData.files[].readOrder`, and the internal composition of the reads by `readStructure`.
  - Added per-value explanations to the descriptions of `sequencingLayout`, `platformCategory` and `sequencingScope`. The previous `libraryType` description was just "Library type", which left every value unexplained.
  - Added `I1` and `I2` to `donors[].labData[].sequenceData.files[].readOrder`, so that submitted index-read files can be identified; previously only `R1` and `R2` were expressible.
  - Clarified that `donors[].labData[].barcode` holds the barcode sequence itself, its position being described by `readStructure`.
  - **BREAKING**: `donors[].labData[].tissueOntology.name` is now a controlled value, either `BRENDA Tissue Ontology` or `other`; free-text ontology names no longer validate. The field was previously unconstrained, so `BTO`, `Brenda`, `brenda tissue ontology` and any misspelling were equally acceptable and the accompanying `tissueTypeId` could not be reliably attributed to a vocabulary — an identifier is only interpretable once it is known which ontology issued it. Settling on a single ontology is what makes the identifier usable; BRENDA is proposed because it is the vocabulary the tissue fields of the receiving research archive accept, so identifiers can be passed on without a mapping step. If a different ontology is used, its name must be given in the new `tissueOntology.nameOther`. Where BRENDA is declared, `tissueTypeId` must match the BTO identifier format `^BTO:[0-9]{7}$`.
  - **BREAKING**: if BAM or FASTQ files are submitted for a DNA variant-calling library of a donor (`sequencingScope` of `wgs`, `wxs` or `panel`), at least one VCF file must be submitted for that same donor, so that research-consented submissions can be reanalysed without reprocessing the raw sequence data. The requirement is counted per donor deliberately: it makes every VCF unambiguously attributable to a donor, which a per-submission rule cannot do, since the schema cannot inspect which sample columns a jointly genotyped VCF contains. Where variants are called jointly across a trio, the resulting VCF must therefore be listed under each donor it covers; the same file may be declared more than once. A tumor/normal pair belongs to a single donor, so its joint VCF is provided once. Libraries whose scope is `other` or `unknown` are exempt, since they need not produce VCFs. The rule applies to every `submissionType`, so raw reads cannot be delivered ahead of variant calls. Submissions with no BAM or FASTQ files, and empty `files` lists, remain valid as before.
## [1.3.0] - 2025-10-07
### Changed
  - Version bump only; no changes to the schema structure or validation rules.
  - Corrected the version string from `1.3` to `1.3.0` to conform to semantic versioning.
## [1.2.3] - 2025-09-05

  - Added `researchConsents` to  `donors` required properties.
  - Added `noScopeJustification` to `donors.researchConsents`.
### Changed
  - Changed `researchConsents` required properties to `presentationDate` and either `scope` or `noScopeJustification`.
